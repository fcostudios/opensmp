# Stryker sandbox exclusions — measured effect

Measured 2026-08-15 on the `smp` main checkout at `09d5266`. This measures the
`stryker.conf.json` `ignorePatterns` expansion from `[".tmp/**"]` to the
seven-entry set (`.turbo`, `.vercel`, `out`, `.tmp`, `.worktrees`,
`docs/screens`, `docs/mocks`).

Stryker does **not** read `.gitignore`. Every path above is already gitignored
or generated, yet all of it was being copied into the Stryker sandbox and
preprocessed on every campaign startup. That is the defect this fixes.

## Why the CHG-014 representative campaign was NOT used

The obvious measurement — the fixed two-shard representative campaign in
[`CHG-014-local-mutation-cache.md`](CHG-014-local-mutation-cache.md) — is
**structurally incapable of observing this change**. Three independent reasons:

1. `scripts/benchmarks/chg014-representative-fixture.mjs` refuses any checkout
   that is not clean, and in the applied state requires the two fixture files to
   be "the repository's only changes". A modified `stryker.conf.json` is refused
   outright.
2. `git show 71086076…:stryker.conf.json` carries the old `[".tmp/**"]`. The
   "after" arm cannot exist in that worktree without making it dirty, which
   reason 1 then rejects.
3. The campaign runs in a **fresh detached worktree** built by
   `git worktree add` + `pnpm install --frozen-lockfile`. All 4,513 `.turbo`
   files are turbo *build cache* — an artifact of a long-lived working checkout.
   A fresh worktree has none. The exclusion set targets detritus that is
   definitionally absent from the fixture environment.

That doc's own text corroborates this: it reports the fixture campaign scanning
"roughly 950 repository files", versus **5,702** in the main checkout. The
fixture already sits at approximately the post-fix state.

This measurement therefore uses the main checkout directly, isolating the
mechanism the change actually affects: **per-Stryker-startup sandbox creation**.

## Method

One small, DB-free shard — `packages/domain/src/alerts/approval-aging.ts`
(84 lines, colocated test, 51 mutants) — run via `npx stryker run <conf>`
directly, bypassing the cache orchestrator so every run is cold by construction.

Two throwaway configs, identical except for `ignorePatterns`, both written to
`.tmp/` (excluded by *both* arms, so the config files themselves cannot bias
the count):

- **Arm A** — `.tmp/stryker-armA.conf.json`, `ignorePatterns: [".tmp/**"]` (pre-change)
- **Arm B** — `.tmp/stryker-armB.conf.json`, the seven-entry set (post-change)

Four runs per arm, interleaved A/B to be fair against machine drift.

## Result

| Metric | Arm A (before) | Arm B (after) | Delta |
| --- | ---: | ---: | ---: |
| `Found 1 of N file(s)` | **5,702** | **1,132** | **−4,570 (−80.1%)** |
| Wall-clock, 4 runs (s) | 9.95 / 9.09 / 8.80 / 7.41 | 4.00 / 3.96 / 3.83 / 3.76 | — |
| Wall-clock mean (s) | 8.81 | 3.89 | **−4.92** |
| `DisableTypeChecksPreprocessor` warnings | **29** | **0** | −29 |
| Mutation score | 100.00% | 100.00% | unchanged |
| Mutants killed / tests run | 51 / 7 | 51 / 7 | unchanged |

The file count and warning count were **byte-identical across all four runs of
each arm** — this is deterministic, not noisy.

### The file-count delta decomposes exactly

| Source | Files |
| --- | ---: |
| `.turbo` (root 4,479 + nine nested `packages/*` and `apps/*` dirs, 34) | 4,513 |
| `docs/screens` | 57 |
| **Total** | **4,570** |

This matches the observed 5,702 → 1,132 delta exactly. `.tmp` contributes zero
because arm A already excluded it. `.vercel`, `out` and `docs/mocks` are absent
from the checkout; `.worktrees` exists but is empty.

**This confirms the IMP-367 finding on Stryker pattern semantics**: bare names
match at any depth. The 34 files in nested `packages/*/.turbo` and
`apps/*/.turbo` were caught, which a root-only `dir/**` glob would have missed.

### Parse warnings

Answered directly: **yes, they disappear — 29 → 0.** All 29 were
`DisableTypeChecksPreprocessor` failures against `docs/screens/SCR-*.html`
("Opening tag "p" not terminated"). This is the "repeatedly attempts to
preprocess unrelated generated screen HTML" cost named in the CHG-014 doc.

## Projection to a full campaign — and its honest limit

Sandbox creation is a **fixed per-Stryker-startup cost**, largely independent of
shard size. Every shard config generated by `scripts/mutation-scope.mjs` was
verified to carry the new `ignorePatterns` (21 configs, from that script's
fixture run against the current diff), so every shard benefits.

The US-025 route-accountability campaign — the largest cited production
campaign, and the basis for the projection below — ran **18 shards**:

- 18 × 4.92 s mean ≈ **89 s** (~1.5 min) saved
- Steady-state pairing, run 4 vs run 4 (7.41 − 3.76) → 18 × 3.65 s ≈ **66 s**

Against that campaign's **1,563 s** cold wall time, that is roughly a
**4–6% reduction**.

> **Do not read the 80% file-count drop as an 80% time saving.** Cold campaign
> time is dominated by actual mutant execution, not sandbox setup. The 80% is a
> real and exactly-verified reduction in files copied and preprocessed; the
> wall-clock consequence on a full cold campaign is single-digit percent.

Arm A's wall-clock declined monotonically across its four runs (9.95 → 7.41)
while arm B stayed flat (4.00 → 3.76), consistent with OS page-cache warming
over the 4,513 `.turbo` files. Steady-state saving is therefore likely nearer
the low end of the range. The 89 s figure is **measured per-startup × a cited
shard count**, not a measured end-to-end campaign time; no cold/cold production
pair was run.

## Guard: no test regression

The handoff guard was "if any test that passed now fails, an exclusion removed a
fixture."

- Arm A and arm B produce **identical** results: 7 tests, 51 mutants, 100.00%.
- `node scripts/test-mutation-scope.mjs` passes (exit 0) with the new config.
- No source or test resolves `docs/screens` or `docs/mocks` at runtime. The 11
  matches are scaffold *comments* in `apps/web/src/app/**/page.tsx` pointing at
  `docs/screens/SCR-*.json` spec files — not the excluded `.html`, and not
  resolved at test time.
- No source references `.turbo`, `out`, `.vercel` or `.worktrees`.
- **By inspection, not execution:** `docs/specs` is not in the exclusion set, so
  it cannot have been removed from the sandbox, and the
  `docs/specs/07c_navigation_map.json` resolution used by `sidebar.test.ts`,
  `route-access.test.ts` and `screen-access.test.ts` is unaffected. Those three
  tests were not located or run here — the shard measured does not exercise
  them.

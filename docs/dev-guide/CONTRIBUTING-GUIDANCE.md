# Contributing project guidance

Some docs in this package are **generated by Nous** and re-emitted on every sync.
Editing one directly does not work: the sync refuses the file to avoid destroying
your edit, and from then on it stops receiving substrate corrections too. You keep
your paragraph and lose every future fix.

Put project-specific guidance in **`docs/dev-guide/local/`** instead.

## How it works

1. Create `docs/dev-guide/local/<name>`, named after the doc it extends.
2. Write whatever your team needs. The file is **yours** — Nous never rewrites it.
3. The next sync inlines it verbatim into the generated `<name>`, under a
   `## Project additions` heading.

Because the content goes *through* the generator, the generated file stays
verified: your guidance survives, and substrate corrections keep arriving.

## Which files can be extended

| generated doc | extend it with |
|---|---|
| `CLAUDE.md` | `docs/dev-guide/local/CLAUDE.md` |
| `CONTRIBUTING-GUIDANCE.md` | `docs/dev-guide/local/CONTRIBUTING-GUIDANCE.md` |
| `DEFINITION_OF_DONE.md` | `docs/dev-guide/local/DEFINITION_OF_DONE.md` |
| `FEEDBACK.md` | `docs/dev-guide/local/FEEDBACK.md` |
| `FRONTEND.md` | `docs/dev-guide/local/FRONTEND.md` |
| `SECURITY.md` | `docs/dev-guide/local/SECURITY.md` |
| `STANDARDS.md` | `docs/dev-guide/local/STANDARDS.md` |
| `TESTING.md` | `docs/dev-guide/local/TESTING.md` |

`CLAUDE.md`'s extension also reaches `AGENTS.md`, `CODEX.md`, `.cursorrules` and
`.github/copilot-instructions.md` — they are renderings of the same document, so
there is one local file, not five.

A file in `docs/dev-guide/local/` that is not named after a generated
doc is reported during generation and inlined nowhere.

## Rules

- **Never edit a generated doc directly.** If you already have, run
  `nous_package.py adopt --target <this package> --relocate <path>`: it lists the
  differing sections and moves the ones you pick into
  `docs/dev-guide/local/`.
- **Not every difference is yours to keep.** Where this package *corrects* a
  generated fact — a framework version, a package layout, a stack detail — the fix
  belongs in the project's configuration, not in a local file. Relocating it
  freezes a value that will go stale and never be updated.
- **No provenance markers.** A `nous-emitted` comment in a local file is refused:
  the generator stamps the emitted doc, and a marker here is either silently
  stripped or a false claim.
- **Commit `docs/dev-guide/local/` to your repository.** It is the only
  copy. `nous_package.py generate --clean` wipes everything except `.git` and
  `node_modules`, so your git history is the recovery path.

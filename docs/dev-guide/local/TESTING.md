## SMP implementation and evidence notes for the critical set

Where the tests behind each critical path live in this package. Tenant-owned (relocated from the emitted §3 on 2026-11-02); per-story evidence goes in feedback events.

- **Tenant isolation** — every path that touches tenant-scoped data (filtered by `company_id`). → explicit isolation assertions (a query for tenant A must never return tenant B's rows). US-036: `apps/web/src/modules/statements/repository.integration.test.ts` and the signed-session statement-detail route seam assert finance-grant scope for headers, lines and exact US-033 register assignments; a concurrent draft rerun must preserve one repeatable-read snapshot. US-037: `apps/web/src/modules/statements/export.integration.test.ts` verifies company-scoped CSV reads, company-language labels, exact stored USD values, and audit-before-download atomicity; foreign identifiers and non-finance grants yield no data or successful-export audit. missing read grants yield no data or successful-export audit.
- **Authorization** — role/permission gates on commands/mutations. → integration tests for allowed vs forbidden (expect 403). US-048 backup/guarded restore also asserts PostgreSQL 16 public-schema object ownership, preserved security-definer EXECUTE restrictions, no backup-role CREATE grant, and restore-window revocation against a real database. US-041: scoped finance/approver/viewer read capability oracles in `packages/domain/src/identity-access/authorization.test.ts`; signed-session statement list/detail isolation and denied foreign URLs in `apps/web/src/app/(authenticated)/estados-de-cuenta/[statementId]/page.integration.test.tsx`; real-DB statement and register tests pin evidence/export scoping. Viewer read grants confer no command capabilities.
- **Money / tax / financial math** (if present) — amounts, rounding, and idempotency of charge/ledger events. → property-based + a provider contract test. US-039: `apps/web/src/modules/close/rollup.integration.test.ts` constrains five-company CSV signed-cent conservation, US-096 group sums and same-snapshot US-038 contribution completeness. Missing vendor scope, drafts, inconsistent headers and stale reconciliation snapshots must not tie; signed-session close/action and download tests verify period propagation, access and audit-before-download failure.

- **BR-17 — Proration is daily actual/actual with exact mid-month boundaries** — critical business rule; oracle: `exact`. (stories: US-034). Implementation: `packages/domain/src/close/license-close.ts`; exact transfer-on-10th oracle and seeded split-conservation/rounding properties in its adjacent test.
- **BR-18 — Close is deterministic and idempotent; finals are immutable** — critical business rule; oracle: `exact`. (stories: US-034, US-035, US-047, US-050, US-096). US-096: `apps/web/src/modules/statements/list-repository.integration.test.ts` verifies stamped period reads, exact signed group sums, rerun replacement and finance-grant isolation; signed-session page checks cover both screens and rerun invalidation in `apps/web/src/app/(authenticated)/cierre/page.integration.test.ts`. US-035: the same real-PostgreSQL seam exercises confirmed single/period finalization, rate locking and stale-rate rejection, scoped role checks, audit atomicity and next-draft corrections; `finalization-panel.test.tsx` exercises explicit confirmation and command feedback. US-034: `apps/web/src/modules/close/close-service.integration.test.ts` checks stable line bytes, draft reruns, final/reconciled immutability, rollback, company isolation and finalization races against app-role PostgreSQL.
  US-051: manual and scheduled execution share `packages/db/src/license-close.ts`; the close-service PostgreSQL seam retains deterministic totals, rollback and immutable-final checks and asserts persisted in-progress runs, scheduled failures without statements, and tenant/period-scoped tile totals. The worker close-schedule seam verifies bd-3 scheduling with holidays, distinct no-op execution keys and the independent weekend/missing-run watchdog.
- **BR-20 — Reconciliation flips to reconciled ONLY within 0.5%** — critical business rule; oracle: `exact`. (stories: US-038). Implementation: `packages/domain/src/close/reconciliation.ts` uses integer cents and the inclusive invoice-denominator boundary; `apps/web/src/modules/close/reconciliation-transaction.ts` compares finalized per-org statement contributions. Seeded money properties, real app-role PostgreSQL command/tenant/immutability/audit oracles, signed-session page/actions and the committed migration guard test constrain the rule.
- **BR-22 — Company scoping is enforced server-side on every query** — critical business rule; oracle: `exact`. (stories: US-005, US-047, US-094, US-095, US-096, US-097)
